# Свой остров · Первый берег

Мобильная браузерная игра с 3D-островом и рабочими сменами. Клиент использует Vite, TypeScript, Three.js / WebGL 2, HTML и CSS. Интерфейс на русском.

## Запуск и проверка

Node.js 22.12+ (проверено на 24), npm и браузер с WebGL 2.

```bash
cd client-web
npm ci
npm run dev -- --host 0.0.0.0
npm test
npm run build
npx vite preview --host 0.0.0.0
```

Разработка: http://localhost:5173. Production preview: http://localhost:4173. На телефоне в одной сети откройте сетевой адрес из терминала. Сборка сохраняется в `dist/`.

## Управление

- В начале интерфейс свёрнут. Кнопка ☰ внизу справа открывает панели управления.
- Один палец или левая кнопка мыши: перемещение карты по земле, без вращения.
- Два пальца: масштаб и перемещение. Колесо мыши или кнопки +/−: масштаб.
- Панорамирование ограничено открытой сушей. На обычном мобильном масштабе северный предел оставляет примерно 40–45% верхней пелены, южный — 30–35% нижней водной полосы. Боковые пределы также не дают уехать от острова. Границы пересчитываются при зуме и смене размера экрана.
- При сильном отдалении, когда обе доли одновременно геометрически недостижимы, диапазон панорамирования сжимается до позиции осмотра острова. Зум при этом не меняется; точные проценты вне этого допустимого диапазона не гарантируются.
- Кнопка ⌖: вернуть весь остров в исходный изометрический ракурс. Ортографическая камера вписывает фактический 3D-объём острова примерно на 96,5% ширины портретного экрана, учитывает высоту зданий и перестраивается при изменении размера экрана. Границы перемещения рассчитываются из данных карты.
- «День / Ночь»: плавная смена освещения. «Автосмена» на большом экране переключает фазу каждые 35 секунд активного времени.

## Данные и подключение API

- `src/data/cells.json` — статическая тестовая карта, не генератор. Массив клеток с координатами `q`, `r`, местностью `type`, высотой поверхности `height`, состоянием `state`, необязательными `building`, `rotation` (градусы) и `variant` (вариант декоративной модели 0–2).
- `src/map-data.ts` — типы DTO, проверка данных, интерфейс `MapSource`, локальный и HTTP-источники, расчёт рамки карты.
- `src/hex.ts` — осевая pointy-top сетка → плоскость XZ, вертикальная ось — Y.
- `src/island.ts` — загрузка моделей, отображение клеток, трёх вариантов леса/гор, песчаного берега и выделения. Модели и текстуры повторно используются клонами.
- `src/camera.ts` — кадрирование и пределы осмотра открытой суши с учётом верхней пелены, нижней водной полосы и масштаба.
- `src/fog-sampling.ts` — оценка непрозрачности тумана для границ камеры.
- `src/atmosphere.ts` — более светлое мелководье, переход к глубине и лёгкая движущаяся рябь.
- `src/northern-fog.ts` — единый северный объём тумана в мировых координатах. При интегрировании плотности используется глубина видимой поверхности, поэтому туман скрывает землю, горы и деревья внутри области, а ближние объекты остаются ясными.
- `src/scenery.ts` — небольшие неравномерные рощи и связанные горные группы с одной главной вершиной; исходные клетки не меняются.
- `src/main.ts` — сцена, камера, атмосфера, время суток и обновление карты. Стрелки перемещают карту, +/− меняют масштаб, Home возвращает камеру.

Трёхмерная сцена загружает мир через `GET /game/progress` в той же гостевой сессии, что и рабочие смены. `src/world-api.ts` читает открытые клетки из сохранения. Статическая карта из `cells.json` используется в тестах и при локальном предпросмотре `?match3-preview`.

```json
[{"q":0,"r":0,"type":"grass","height":0.65,"state":"visible","building":"townHall","rotation":0}]
```

Клетки острова отображаются без карточек. Раскопки доступны через «Рабочие смены». При успехе клиент перечитывает карту и подсвечивает открытый участок.

## Ассеты и ограничения

Модели — из предоставленного архива KayKit Medieval Hexagon Pack. В `public/kaykit/` сохранены используемые glTF, связанные `.bin` и PNG. ZIP в проект не добавлен. Новые здания используют красный вариант моделей; модель церкви представляет ратушу, рынок — склад, поле зерна — ферму. Отдельного файла лицензии в предоставленном архиве нет.

## Рабочие смены и 3 в ряд

Кнопка «Рабочие смены» открывает лесопилку, ферму, каменоломню, рудник и раскопки. Сервер сохраняет поле, остаток ходов и зарядов, глубину раскопок и запасы склада. После перезагрузки откройте «Рабочие смены», чтобы продолжить активную партию.

1. В каталоге `game-unknown-backend` поднимите API и PostgreSQL командой `docker compose up -d --build --wait`. Нужна версия бэкенда с миграцией `004_match3`, которую Compose применяет при запуске.
2. В `client-web` запустите `npm run dev`. Vite передаёт запросы `/game/*` на `http://127.0.0.1:8000`. Если API слушает другой адрес, задайте `GAME_API_TARGET` в `.env.local`.
3. Для проверки с телефона в той же сети запустите Vite с `npm run dev -- --host 0.0.0.0` и откройте выведенный адрес Vite. Для готовой сборки настройте прокси `/game/*` на том же домене, что и игра. Гостевая сессия хранится в cookie.

Фронтенд отправляет действия через `src/match3-api.ts` и проигрывает полученные шаги каскада. Результат и начисление рассчитывает сервер. Настройки ресурсов и игровых ручек описаны в [контракте API](https://github.com/gamezavod/game-unknown-backend/blob/main/docs/match3-api.md).

Производительность на физических телефонах требует отдельного замера: браузерная проверка использует эмуляцию touch/viewport в Chromium. DPR ограничен 1.75. Вода использует слабую рябь, туман — объёмное рассеяние с текстурой глубины и 16 шагами в переходной области; для чистого и полностью туманного участка расчёт упрощён. Промежуточный буфер с двумя выборками сглаживания использует HalfFloat при доступности `EXT_color_buffer_float`, иначе обычный RGBA. Vite предупреждает о размере основного JS-бандла Three.js (около 624 КБ до gzip).
